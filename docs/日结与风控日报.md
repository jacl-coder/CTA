# 日结与风控日报

更新日期：2026-09-10。唯一外部依据为[机试原题](机试题目-多品种期货交易风控系统.md)中的收盘逐日盯市、盈亏和保证金核算、风控日报要求。下面的会话边界、封账步骤、文件格式和恢复方式是本项目为实现这些要求作出的设计。

## 已接通的流程

新增清算计划声明每个交易日的收盘帧和独立结算价。行情接入、下单、收盘、清算和结转全部复用原有 `LedgerService` 有界队列，只有一个业务消费者修改状态。核算仍调用既有 `settle_account`、`start_next_day` 和估值函数，没有在存储或报表中另写盈亏公式。

交易日依次经历 `OPEN`、`CLOSING`、`SETTLED`：

1. `OPEN`：完整行情有效时执行原有交易规则。自动模式到达收盘时刻后，订单执行入口立即停止放行，不依赖定时任务是否已被调度。
2. `CLOSING`：收盘命令持久化后，拒绝新的开平仓，继续补齐该日收盘帧以内的行情并计算风险。缺失最后一帧也不能清算，不能跳到下一日行情。
3. `SETTLED`：全部账户清算结果、账本修订、交易日志和冻结日报快照在同一事务提交。仍拒绝当日交易，结算结果禁止覆盖。
4. 下一日：必须完成前日清算且目标为计划中紧邻的下一交易日。单独事务结转期末余额、重置剩余持仓结算基准，清零当日已实现盈亏与费用，保留原成交及开仓日期。下一日首帧到达并评估风险后才能交易。

收盘与清算分开是为了让断线恢复有明确的等待状态。原始数据可以提前收到下一日，但完整业务帧不能越过未完成的前日日结。清算计算失败不修改账本；数据库事务失败停止业务写入，重启后从已提交状态恢复并重试。

## 交易日与行情边界

行情序号在整个运行内连续，不在跨日时重置。可选的 `market.sessions` 声明每个交易日最后一帧，首日必须等于账本初始化日期，日期和结束序号严格递增，最后一日结束帧必须等于总帧数。未配置会话的原双源场景仍按单交易日运行，已有冻结场景兼容。

两日示例是 2026-09-09 的第 1–64 帧和 2026-09-10 的第 65–96 帧。第 64 帧存在一个完整报价间隔，其结束时刻 `epoch_ms + 64 × interval_ms` 为首日收盘时刻。源生成的每帧携带所属交易日；真实时间只推进模拟逻辑时间，不用机器自然日期判断夜盘归属。

`settlement.days` 与行情会话边界必须完全一致，每日明确提供全部配置合约的结算价。结算价允许不等于最新价，也不要求满足成交最小价位，但必须满足既有结算价格精度与范围要求。缺少结算价在启动前拒绝配置。实际清算请求还会核对冻结计划，禁止补传一个不同价格覆盖历史。

这是有限场景日历，支持声明多个交易日，但不声称包含真实交易所夜盘、节假日或结算价发布接口。恢复使用原来的运行配置与数据库；配置中的账本日期始终表示初始化首日，不能修改它来代替结转。

## 核算与次日风险

清算以当日平仓盈亏加剩余持仓的盯市盈亏，扣除当日手续费，得到净盈亏与期末余额。保证金按结算价重新计算，作为资金占用而非费用，不从权益重复扣减。明细按批次保留基准价、结算价和盈亏，汇总使用 Decimal，跨接口和文件的金额均为字符串。

当日结算完成时保留该日账本和结算结果，直到下一日结转才重置持仓基准。下一日平昨使用前日结算价计算当日盈亏，保留原开仓价供追溯。跨日不会重新计收历史成交手续费，历史成交及平仓分配继续留存；当前账户查询仅返回本日累计费用与盈亏。

前日亏损熔断在成功结转时重置，告警与敞口限制也重新评估。此时尚无次日有效报价，交易仍被阻止；首帧按次日持仓基准和原冻结规则计算，必要时再次限制或熔断。原始初始资金保持不变，仍作为本项目浮亏阈值基数。

风险事件增加可查询的 `trading_day`，由触发帧归属确定。日报中的风险状态与事件数来自该日收盘行情处理结果；资金、保证金与敞口来自独立结算价估值，二者价格口径不同，不用结算价补造盘中风险事件。

## 幂等、事务与重启

`application/settlement.py` 提供可重放的收盘、清算和结转转换，交易日志记录每次有效操作及计算结果。收盘重复调用返回原阶段，已结算交易日同价重试返回 `duplicate=true`；即使已经进入次日，仍可查询和重试前日日结。不同价格、缺价格或不在计划内的日期明确拒绝。新订单编号仍在整个运行的账户范围内唯一，跨日不要复用旧订单编号。

迁移 `004_settlement.sql` 增加冻结清算配置和按交易日唯一的日报快照。全部账户日结与全部账户结转分别采用单事务，更新账本修订号、余额、持仓和交易日志。历史成交及平仓分配不删除；读取当前账本时按成交交易日选择本日平仓分配。

恢复时从初始化成交开始顺序重放行情、订单、收盘、清算和结转，并核对当前账本、报告全文及摘要。修改报告后重新计算摘要也不能绕过日志重算核对。重放还累计各交易日的平仓分摊，核对完整历史表，避免只检查当前日而遗漏历史审计数据损坏。已应用行情及风险事件的原有完整性校验继续执行。

## 日报格式与文件失败重试

每日日报 JSON 包含运行标识、交易日、收盘序号、配置及规则摘要、结算价、全账户结算明细、敞口估值、收盘风险状态和事件数，以及资金与敞口汇总。它在财务事务内冻结，是生成文件和下载数据的依据。

`report/exporter.py` 只展示快照，使用标准库 `html.escape` 转义所有文本，生成中文独立 HTML 和原文 JSON。早期设计中的 Jinja2 在这一阶段调整为标准库渲染，避免为固定格式增加运行依赖。HTML 内置样式，无外部脚本或网络资源，可以离线打开。

文件名为 `risk-YYYY-MM-DD.html` 和 `risk-YYYY-MM-DD.json`，只取经过日期校验的交易日。输出目录由配置决定，应为每个运行指定独立目录。先写临时文件、刷新后分别原子替换目标文件；两个文件之间不构成数据库事务，但都来自同一个冻结快照，重试可以补齐。

文件写入失败不撤销清算，不重复入账，也不妨碍已清算持仓按计划结转；状态接口展示 `report_errors`，后台继续重试，还可手工触发导出。重启后重新导出已提交报告。数据库清算失败与文件导出失败分开处理。

## 使用方式

在仓库根目录运行：

```bash
# 临时目录内完成两日真实 HTTP 验收，自动退出并清理
make demo-settlement

# 手动查看新的两日双源场景、接口及生成的文件
make run-sources
```

固定场景读取 [settlement-demo.yaml](../configs/settlement-demo.yaml)，后端 8003，行情源 8201/8202。96 帧默认每帧 250 ms，约 24 秒完成两日自动日结；每次展示的数据位于新的 `var/source-runs/<时间标识>/` 目录。重复自动核对使用临时验收脚本。

访问 [API 文档](http://127.0.0.1:8003/api/docs)，写操作继续使用 `/api/session` 获得的本地 Bearer 令牌：

- `GET /api/settlement/status`：当前交易日、阶段、收盘边界、应用进度、已结算日期和文件导出错误。
- `POST /api/settlement/close`：请求体 `{"trading_day":"2026-09-09"}`，停止当日新增交易，等待缺失行情补全。
- `POST /api/settlement/settle`：请求体增加 `prices` 字典，使用对应冻结计划中的十进制价格字符串；需已封账且行情齐全。
- `POST /api/settlement/open`：请求下一交易日，仅允许已清算后结转到计划中的下一日。
- `GET /api/reports`：已提交的日报日期列表。
- `GET /api/reports/2026-09-09`：查询冻结 JSON，文件导出失败时仍可用。
- `POST /api/reports/2026-09-09/export`：重新导出该日 HTML/JSON，返回文件名；失败返回 503 并保留清算结果。
- `GET /api/reports/2026-09-09/download/html` 或 `/json`：下载已导出的文件。

手工演示可将 `auto_settle` 设为 `false`；没有自动行情时必须关闭它，手工价格仍须按计划日期和连续序号提交。自动与手工操作走同一队列和转换，重复执行不会重复入账。尚未到收盘也可手工提前进入 `CLOSING`，之后仍须收到计划收盘帧才能清算。

无会话令牌返回 401；未启用日结返回 503；无报告返回 404；日期、阶段、行情完整性错误返回 422；结算价格与冻结计划冲突返回 409。已封账或清算后的新订单返回业务拒绝 `TRADING_DAY_CLOSED`，收盘边界已到但定时任务尚未执行时可返回 `MARKET_UNAVAILABLE`，均不产生成交。

## 独立手算与验证

两日样例继续使用 A/B/C 三账户和三个交易所合约。首日结算价为螺纹钢 3510、铁矿石 810、股指 4005；与收盘前行情不同：

- A：已实现 100，剩余 2 手持仓盯市盈利 200，手续费 8，净盈亏 292，期末 100292，保证金 7020。
- B：2 手铁矿石空仓盯市亏损 2000，手续费 6，净盈亏 -2006，期末 197994，保证金 19440。
- C：1 手股指多仓盯市盈利 1500，手续费 5，净盈亏 1495，期末 1001495，保证金 144180。

次日验收脚本在螺纹钢 3520 时平 A 昨仓 1 手，以前日结算价 3510 为基准，已实现盈亏 100、手续费 2。次日结算价为 3490、800、4010：

- A 剩余 1 手亏损 200，净盈亏 -102，期末 100190，保证金 3490。
- B 净盈亏 2000，期末 199994，保证金 19200。
- C 净盈亏 1500，期末 1002995，保证金 144360。

`make run-sources` 只运行行情和自动清算，不自动提交平昨订单，因此它的 A 次日期末是 99892、剩余 2 手；上面的 100190 对应 `make demo-settlement` 实际提交了平昨的验收流程。

测试包含收盘缺口跨两个交易日后恢复、`CLOSING` 重启、越过收盘边界立即拒单、全账户事务中途故障与重试、日结/结转重复操作、报表修改/删除检测、导出失败后重试及 HTML 转义。真实进程脚本在次日平昨后强制退出后端，恢复验证前日报告不变且重试不重复成交，然后完成第二日日结与文件核对。源码和发布包使用相同验收脚本，具体测试数量和执行结果见[测试方案](测试方案.md)。

## 当前范围

日结使用有限配置场景的逻辑收盘时刻及显式结算价，支持多交易日顺序运行。真实交易日历、外部结算价修订、历史账务更正、跨机器部署和长期数据规模尚未验收。当前前端仍是服务状态页，日结与报表可通过接口、命令演示及离线文件使用；下一步是前端账户与风险业务展示，随后核对附加项和最终交付材料。
