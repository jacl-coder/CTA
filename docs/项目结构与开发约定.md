## 依赖方向

领域模型不导入 FastAPI、Pydantic、SQLite 或 YAML。持仓、估值、规则和清算依赖领域模型；应用层组合业务行为；HTTP、数据库、数据源适配层依赖应用端口，由 `bootstrap.py` 统一装配。只在确实存在 I/O 或替换需求时引入 Protocol，不创建通用全能 service 或工具包。

前端只调用 `/api`，不读取数据库、不计算权威盈亏、不决定风控放行。生成的 API 类型保存在 `frontend/src/api/schema.d.ts`；可复用组件在实际出现多个消费者时提取。

## 状态与金额

当前账本服务使用单个业务协程作为状态所有者，单个 Uvicorn worker 运行；有界队列顺序处理内部成交，SQLite 专用线程提交成功后才发布新快照。已接收成交在调用方取消等待后继续处理，重试使用同一成交编号。后续行情接入、模拟执行和回放接入同一应用入口，不能另建可绕过风控的写路径。

首次建库的初始化成交带明确来源，业务配置冻结在数据库中。每次启动核对配置并从成交重算验证快照，不重复初始化；同一数据库禁止多个写进程。具体契约和当前单交易日限制见[账本接口与持久化](账本接口与持久化.md)。

金融值以十进制字符串跨 API、配置和存储边界，计算使用 Decimal；界面仅格式化展示。手续费、保证金和日结的口径通过独立手算样例固定，不能用被测函数自身生成预期值。

## 测试与生成文件

- `backend/tests/unit` 测纯计算、状态转换和配置；`integration` 测 HTTP、数据库与恢复；端到端业务场景落入后续 `acceptance`。
- 前端组件测试贴近组件，浏览器业务流程落入后续 `frontend/e2e`。
- `make check` 检查 Python、TypeScript 和 lint；`make test` 跑已有测试。
- `make api` 生成的 OpenAPI 与 TypeScript 类型需要提交；前端构建、后端 static 副本、虚拟环境、运行数据与发布目录不提交。
- 新增运行依赖必须在对应清单声明并更新锁文件；不要提前安装尚未使用的行情分析或数据科学依赖。

## 当前验收边界

工程骨架已验证配置、HTTP、前后端与打包；核算基础已验证持仓、估值和逐日盯市领域函数。SQLite、账户初始化、只读查询、事务回滚与重启恢复已接通，详见[计算样例](业务口径与计算样例.md)及[测试方案](测试方案.md)。SSE、交易风控流程、持久化日结、自动清算与模拟源尚未接入，完整系统尚未验收。
