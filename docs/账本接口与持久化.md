# 账本接口与持久化

更新日期：2026-09-10。唯一外部依据为[机试原题](机试题目-多品种期货交易风控系统.md)中的持仓管理要求。本文记录本项目为实现账户独立核算、多维查询及持仓更新而采用的方案；SQLite、队列、表结构与接口字段均为自主设计。

## 当前范围与结构

默认账户、合约及初始化成交来自 [default.yaml](../configs/default.yaml)。首次建库前，以核算领域函数检查所有初始成交，再将配置、成交、账户账本、持仓批次和平仓分配一起提交。后续启动校验配置并恢复已有数据，不重复加载初始化成交。

- `domain`、`position`、`valuation`、`settlement/calculator.py`：不可变模型和纯核算函数，不访问数据库。
- `application/contracts.py`：运行定义、带来源的成交、账本快照与存储端口。
- `application/ledger.py`：初始化与恢复核对、唯一写入队列、事务提交后的快照发布，以及查询用例。
- `storage/sqlite.py`、`storage/migrations/`：SQL 迁移、单事务写入与恢复，不重复实现盈亏或手续费公式。
- `config/ledger.py`：将严格配置转换成应用和领域对象；金融输入使用十进制字符串。
- `api/ledger.py`：只读查询与响应模型。`bootstrap.py` 在 FastAPI lifespan 中装配和关闭服务。

账本单独运行的测试从手工模板移除 `trading` 和 `settlement` 配置；模拟交易模式另见[交易与风控闭环](交易与风控闭环.md)，已提供经过风控检查的下单接口。内部 `record_fill` 保留用于账本适配和测试，启用交易后拒绝此入口，受控成交随交易事务直接入账。没有运行中原始成交导入或手工改持仓的 HTTP 入口。初始化成交标记为 `bootstrap-demo`，仅服务于演示与核算验证，不代表经过了实时风控。

## 启动与配置

在仓库根目录运行 `make run`，访问 `/api/docs`。相对路径以配置文件目录为基准，当前场景的数据库位于 `var/workspace/<运行编号>/ledger.sqlite3`。`check-config`、`create_app` 和 OpenAPI 导出均不建库；数据库在服务启动时打开。

示例账户 A 初始资金 100000.00，开 3 手螺纹钢多仓后平今 1 手，剩余 2 手，当日已实现盈亏 100.00，手续费 8.00，修订号 2。B 持有 2 手铁矿石空仓，手续费 6.00；C 持有 1 手股指多仓，手续费 5.00。合约规则与价格均为演示参数，核算依据见[计算样例](业务口径与计算样例.md)。

运行标识、交易日、账户资金、合约规则及初始化成交一并冻结保存。改变上述业务配置后，已有数据库拒绝启动；应恢复原配置，或为新场景配置新的数据库路径和运行标识。服务端口、数据库路径、队列容量不计入业务指纹。配置字段顺序不影响指纹，业务列表和十进制字符串的表示保留原样，因此恢复时应保留业务配置原文。

一个数据库对应一个运行。首日初始化不导入昨仓；启用清算计划后可在同一运行内跨日，剩余仓位以结算价重置基准并结转为昨仓。配置日期始终表示初始化首日，不能通过修改它代替日结结转。收盘调度、事务与日报见[日结与风控日报](日结与风控日报.md)。

## 查询接口

本节列出的账本接口均为 `GET`，返回 JSON，价格和金融金额使用字符串；数量、序号、修订号使用整数。没有行情时不返回推测的净值、浮盈亏或保证金。`opening_balance` 是当日期初余额，`realized_pnl` 是当日已实现平仓盈亏，`fees` 是当日累计费用，三者不能单独代替实时权益。

- `/api/accounts`：按账户标识排序列出账户账本。
- `/api/accounts/A`：指定账户，包含交易日、初始资金、期初余额、已实现盈亏、手续费及 `revision`。
- `/api/positions?account_id=A&product_id=SHFE.rb`：返回账户/合约/多空方向下的持仓手数、今仓和昨仓。筛选条件可单独使用或组合。
- `/api/positions/summary?product_id=SHFE.rb`：按合约和多空方向跨账户汇总手数。不会抵扣对向持仓，也不将不同合约手数合并成资金敞口。
- `/api/trades?account_id=A&product_id=SHFE.rb&limit=100&offset=0`：按入账顺序返回成交记录、成交手续费和来源。`limit` 默认 100，范围 1–1000；`offset` 从 0 开始。先筛选，再分页。

品种标识带交易所前缀，如 `SHFE.rb`、`DCE.i`、`CFFEX.IF`；具体合约为 `SHFE.rb2610` 等。多空方向表示持仓方向，因此平多仓记录仍为 `side=LONG`，通过 `offset=CLOSE_TODAY` 或 `CLOSE_YESTERDAY` 表示平仓。

不存在的账户返回 404，合法查询没有匹配持仓或品种时返回空列表，非法分页参数返回 422。账本未配置、关闭或存储故障后，查询返回 503。`/api/system` 的 `ledger_available=true` 表示账本可查询；账本查询模式下 `trading_available=false`，`/api/health/ready` 返回 503；模拟交易模式取决于行情有效性，账户规则另行判断。

## 更新与恢复机制

服务以一个有界 `asyncio.Queue` 接收账本模式的内部成交，或交易模式的价格、订单、收盘、清算与结转命令，由唯一消费者调用核算函数生成新账本。SQLite 连接在专用单线程中创建、使用和关闭；一次事务作为一个执行器任务提交，消费者等待它完成才处理下一条成交。队列满时明确返回 `LedgerBusy`，本次成交尚未接收，可以用同一编号重试。

成交身份由运行、账户及 `fill_id` 限定；相同成交重试不增加版本或费用，同编号不同成交内容拒绝。账户内成交序号在每个交易日必须递增，成交编号在整个运行内不重复。来源作为入账审计信息保留，重试不会覆盖原来源。调用方取消等待后，已接收成交继续处理，不能据此认定未成交；通过成交查询核对，再用原编号重试。

数据库使用 WAL、外键与 `synchronous=FULL`。账户修订号更新、成交插入、持仓批次替换及平仓分配写入在同一事务提交。提交后应用才发布新的不可变查询快照；失败完整回滚并将服务置为不可用，重启恢复后再处理成交。正常关闭先停止接收新成交，再处理完已接收的队列。

启动时核对 SQL 迁移校验和、冻结配置及账户/合约目录，账本模式用成交重算，交易模式按行情、订单、收盘、清算和结转日志重放，比对账本及报告快照；发现不一致时拒绝恢复。文件锁阻止第二个账本进程写同一数据库，进程退出后由操作系统释放。当前锁实现依赖 Linux `fcntl`，与首个 Linux amd64 发布目标一致。一个服务使用一个 Uvicorn worker。

上述机制面向本地演示负载。目前成交历史随账本保存在内存，恢复会重算整个运行；尚未声明大规模历史或吞吐量保证，后续根据实际数据量决定是否引入分段恢复与历史存储查询。

## 验证

`make test` 覆盖初始化幂等、并发串行更新、读快照一致性、取消等待、队列满、关闭排空、事务失败回滚、配置冲突、重复写者、恢复数据损坏和查询 API。事务失败测试在账户、成交、持仓和平仓分配均已执行 SQL 后注入异常，核对所有业务表均回到原状态。

`make package` 将 SQL 迁移文件纳入发布目录。`make verify` 在临时目录运行发布程序，检查账户与查询结果；强制终止首个进程后用同一数据库重启，核对结果完全一致，并检查数据库完整性和外键。此项验证本地已提交数据的进程恢复，不代表行情补全或整机断电测试已经通过；发布包的熔断闭环由同一命令中的 `demo_risk.py --packaged` 单独验证。

风控判断、模拟执行、风险日志和事务已接入同一应用入口，详见[交易与风控闭环](交易与风控闭环.md)。双源补全、收盘日结与跨日事务已复用同一队列，下一步接入前端业务展示。
