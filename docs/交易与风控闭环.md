# 交易与风控闭环

更新日期：2026-09-12。外部依据只有[机试原题](机试题目-多品种期货交易风控系统.md)。本阶段对应盘中风控的资金/持仓维度、阈值动作及“浮亏达到阈值后阻止开仓”验收；下文阈值、执行方式、日志结构和接口均为本项目自主设计。

## 已接通的流程

完整模拟价格帧进入应用队列后，对所有账户计算浮盈亏、权益、保证金和品种总名义敞口，更新告警、敞口限制及熔断状态。下单命令进入同一个队列，依次检查行情有效性、账户风控状态、预计持仓敞口及可用资金。通过检查的订单按该帧价格全量模拟成交，其他有效订单保存拒绝结果。

成交、持仓、账户修订、订单结果及风险事件在同一 SQLite 事务中提交，然后发布新快照。当前实现复用原账本服务的唯一消费者，没有增加独立的交易写入协程。

- `domain/trading.py`：订单、价格帧和风险配置的不可变模型。
- `risk/rules.py`：纯风险计算与状态转换，不访问 HTTP 或数据库。
- `execution/simulated.py`：确定性全量模拟成交；成交价格由有效行情决定。
- `application/trading.py`：可重算的交易状态转换、结果及查询视图。
- `application/ledger.py`：同一队列接收价格与订单，组织事务和启动恢复。
- `storage/migrations/002_trading.sql`：冻结交易配置、交易日志及日志修订检查点。
- `api/trading.py`、`api/security.py`：模拟交易 HTTP 接口及本地会话凭据。

## 规则与口径

资金维度采用持仓当日浮亏：所有未平仓批次当日浮盈亏求和，再取负值部分。今仓以开仓价为基准，昨仓以昨结算价为基准；已实现盈亏和手续费计入权益，但不混入该浮亏阈值。

默认浮亏达到初始资金 2% 时告警，达到 3% 时熔断，边界使用“大于等于”。两项比例均可配置，要求 `0 < warning_ratio < loss_ratio <= 1`。3% 是本项目采用的演示值，原题仅将其作为示例。

熔断在本交易日保持，反弹、平仓或重启均不解除，没有当天人工解锁入口。有完整且有效的行情时，熔断账户仍允许合法平仓；不自动强平。其他账户继续独立判断。

持仓维度采用单品种总名义敞口：同品种各合约、多空方向的名义金额绝对值相加，不以净额抵扣。可设置默认额度及账户/品种覆盖值。当前敞口超过额度时限制该账户新增开仓；预计开仓后的敞口超过额度也拒绝，等于额度允许。每笔开仓还检查预计权益减保证金是否非负，计算包含本次成交手续费。

告警和敞口限制分别记录进入/退出事件，退出后再进入可以产生新事件。熔断仅在首次触发时产生 `CIRCUIT_BREAK`，不会随每次价格更新或重试重复发送。解除告警或敞口限制不会清除熔断。

## 运行配置

默认从 `configs/default.yaml` 启动，在页面选择“手工演示”。以下固定配置已移入 testdata，仅供专项测试。账本查询模式由测试按需构造；[presentation.yaml](../testdata/configs/presentation.yaml) 是手工价格驱动的交易与日结展示模板；[market-demo.yaml](../testdata/configs/market-demo.yaml) 保留给固定补数自动验收，详见[双源行情与恢复](双源行情与恢复.md)。

```bash
# 独立临时数据库，自动验证完整熔断场景并退出
uv run --project backend --locked python scripts/demo_risk.py

# 创建干净的手工交易展示
make run  # 页面选择“手工演示”
```

手工模式访问 [工作台](http://127.0.0.1:8004) 或 API 文档。已构建页面由后端直接托管，价格、订单、持仓和风险事件都可在页面操作与核对。

交易配置启动时冻结在 `trading_runs` 中，恢复必须一致；已有交易数据库不允许通过删掉 `trading` 配置来关闭风控。调整规则应使用新的运行和数据库。账本运行切换为交易运行要求账本仍与初始化成交一致，推荐直接使用独立的交易配置。

## 价格入口与有效性

`POST /api/simulation/frames` 是明确标记为 `manual-demo` 的本地价格注入入口。每帧需要包含全部配置合约，价格为正十进制字符串且符合合约最小价位；交易日与运行一致，序号从 1 连续递增。

相同序号、相同内容重试不重算风险、不新增事件，也不延长行情有效期。内容冲突、缺少合约、跳帧或错误交易日拒绝，并暂停交易，直到下一个合法的新帧提交。不会越过缺失帧处理后续价格。

有效期按服务接收帧时的单调时钟计算，默认 30 秒。首次启动、价格过期或进度异常期间暂停所有新开平仓；重启保留历史价格供核对，但标记为非实时有效，必须收到下一个新帧后恢复交易。`/api/risk` 在未收到第一帧时返回空金额，在已有历史价格但无有效实时行情时返回上次计算金额，并明确 `market_ready=false`。

本节有效期和手工注入规则适用于手工演示模式。双源模式禁用该入口，使用两源完整帧自动驱动风险，额外校验当前逻辑进度、连接状态及补全状态；原始行情与已应用进度分别持久化。详见[双源行情与恢复](双源行情与恢复.md)。

## 下单与查询

先 `GET /api/session` 取得本次启动生成的 `token`，在 API 文档的 Authorize 中填入令牌，或在写请求中携带 `Authorization: Bearer <token>`。重启后令牌失效。会话和写接口只接受回环地址 Host；浏览器请求检查同源来源，另允许本地 Vite 5173。令牌不写入配置或日志，会话响应禁止缓存。这是本地演示凭据，不是多用户权限系统。

价格帧请求示例：

```json
{
  "sequence": 1,
  "trading_day": "2026-09-09",
  "prices": {"SHFE.rb2610": "3350", "DCE.i2701": "800", "CFFEX.IF2609": "4000"}
}
```

订单请求 `POST /api/orders`：

```json
{
  "request_id": "A-open-demo-1",
  "account_id": "A",
  "instrument_id": "SHFE.rb2610",
  "trading_day": "2026-09-09",
  "side": "LONG",
  "offset": "OPEN",
  "quantity": 1
}
```

`side` 表示持仓方向；平多仓仍填 `LONG`，并将 `offset` 设为 `CLOSE_TODAY` 或 `CLOSE_YESTERDAY`。用户不能传入成交价格或成交序号。首日配置没有昨仓，平昨会被拒绝；[日结场景](日结与风控日报.md)已实现跨日结转，次日支持平昨。

有效订单返回 HTTP 200，`status` 为 `FILLED` 或 `REJECTED`；需要同时检查业务状态。拒绝原因为 `MARKET_UNAVAILABLE`、`CIRCUIT_BROKEN`、`EXPOSURE_LIMIT`、`PROJECTED_EXPOSURE_LIMIT`、`INSUFFICIENT_MARGIN`、`TRADING_DAY_MISMATCH` 或 `INVALID_POSITION`。拒绝记录没有成交编号、价格或费用，也不改变账本。

幂等键为运行内的 `(account_id, request_id)`。相同订单重试返回第一次结果并标记 `duplicate=true`，包括此前被拒绝的订单；同键不同参数返回 409。需要重新发起一笔业务订单时使用新编号。取消 HTTP 等待不等于取消已接收订单，应先查询最终结果。

- `GET /api/orders?account_id=A`：订单结果，支持 `limit`、`offset`。
- `GET /api/orders/A/A-open-demo-1`：按幂等键查询结果。
- `GET /api/risk?account_id=A`：风险状态、所有当前阻止原因、浮盈亏、权益、保证金、可用资金及总敞口。
- `GET /api/risk-events?account_id=A`：状态转换事件，支持分页。
- `GET /api/market`：最后价格帧、来源和有效性。
- 账户、持仓和成交继续使用[账本查询接口](账本接口与持久化.md)。

`opening_allowed` 表示当前行情与账户状态没有阻止开仓的原因，每笔订单仍需检查预计敞口及保证金。全局 `/api/health/ready` 返回 200 表示模拟交易入口可执行，并不保证所有账户或订单都会放行。未启用交易、缺失/过期行情或存储故障时返回 503。非法参数返回 422，未知账户或查询不到订单返回 404，无凭据返回 401，来源不允许返回 403，队列满返回 429。

启用交易后，内部原始成交导入也会被拒绝，模拟成交直接作为受控交易事务的一部分入账。HTTP 没有直接改持仓或绕过风控导入成交的接口。

## 持久化与恢复

交易日志每条保存已处理命令、订单或帧结果、风险状态、新风险事件及生成的成交信息。日志、账本和日志修订检查点在同一事务提交；检查点用于发现日志缺失，包括没有后续成交的最后一条熔断帧被删除。

启动时从初始化账本顺序重算交易日志，核对每条结果及最终成交账本，恢复告警、限制、熔断和幂等结果；发现不一致拒绝运行。订单是否获得有效行情由原处理时记录的条件重放，重启不会把历史时间误判为当前新鲜行情。失败事务不发布内存状态，服务停止业务操作，恢复后可用原编号重试。

交易日归属由发生帧确定，事件查询附带 `trading_day`。日结后禁止交易，成功结转后重置前日风险状态，等待次日首帧重新评估。

当前完整运行日志保存在内存，启动会全量重算，适用于本机试演示规模；尚未承诺长周期历史处理性能。此处重放用于恢复核对，不等于附加项的历史场景回测工具已经完成。
