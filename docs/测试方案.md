# 测试方案与需求实现进度

外部验收依据只有[机试原题](机试题目-多品种期货交易风控系统.md)；[需求基线](需求基线.md)是内部索引。更新日期：2026-09-10。

本文的需求编号、测试步骤和固定样例均由本项目编写。FIFO、幂等、事务恢复等测试用于验证我们选择的实现；是否满足机试要求，最终要按原题功能、指定熔断场景和交付条款判断。

## 当前已验证的范围

- **POS-01**：领域层支持多空、平今、平昨、FIFO、部分平仓、成交幂等与冲突拒绝。应用层已将当日已成交事实、持仓批次、费用及盈亏一起持久化；执行适配层及跨日存储尚未接入。
- **POS-02**：API 按账户或交易所限定的品种标识查询；无需行情即可返回数量及今昨仓，账户与成交查询支持金额字符串输出。估值与资金敞口仍为领域计算能力。
- **POS-03**：已明确首次建库的配置来源与 `bootstrap-demo` 标记，验证单写者事务更新、重复初始化防护及重启恢复；运行中的成交来源仍待模拟执行接入。
- **POS-04**：验证账户独立核算与数据库更新隔离，查询 API 按同合约同方向跨账户汇总手数。领域层可汇总品种净/绝对名义敞口，对向持仓不跨账户抵扣保证金；完整交易流程尚未验收。
- **SET-01**：领域层逐日盯市、盈亏与保证金、日结明细、重复日结、跨日结转已验证；不等于收盘封账、事务日结和定时调度已实现。
- **RISK-02 的输入基础**：账户浮盈亏、权益、保证金、净敞口及绝对敞口可以计算；规则阈值、风险动作与熔断尚未实现。

核算代码为 `domain/models.py`、`position/book.py`、`position/query.py`、`valuation/calculator.py`、`settlement/calculator.py`；账本编排、存储和 HTTP 分别位于 `application/ledger.py`、`storage/sqlite.py`、`api/ledger.py`。核算与账本测试使用 `pytest.mark.requirement` 关联内部需求编号。

## 固定核算预期

先按[业务口径与计算样例](业务口径与计算样例.md)独立计算，再将结果记录到 `testdata/expected/accounting-two-days.json`。预期值不由被测计算函数生成。

三个账户、三个交易所示例合约、两个连续交易日覆盖开仓、平今、平昨、部分平仓、空仓结算与跨日基准重置。每个账户核对平仓盈亏、持仓结算盈亏、费用、日净盈亏、余额、保证金和可用资金，同时核对清算明细与汇总。

边界测试包括：

- 超量平仓、错误今昨仓或多空方向，不产生部分状态变更。
- 重复成交不重复入账，相同编号不同内容拒绝。
- 账户、合约、交易日不匹配，成交乱序和合约规则变化拒绝。
- 有持仓却缺少行情/结算价时明确失败，不能使用零价格。
- 结算后禁止追加成交；重复相同价格日结返回原结果，不同价格不能覆盖；未日结不能跨日。
- 二进制浮点数、NaN、Infinity、非法数量和超范围输入拒绝。
- 调用方改变 Decimal 全局精度、舍入方式或陷阱设置，不影响核算。
- 同一多空方向拆批不改变保证金，跨账户对向持仓不抵扣资金占用。

## 账本事务与恢复验证

测试位于 `backend/tests/integration/test_ledger.py` 和 `backend/tests/unit/test_ledger_config.py`，使用真实临时 SQLite 数据库及 FastAPI lifespan，覆盖：

- 首次初始化、两次重启、重复成交与冲突成交，不重复计费或覆盖历史来源。
- 20 个并发调用按接收顺序提交，不丢失版本、费用与持仓更新。
- 事务提交前数据库读者和应用查询均只看到旧状态；取消等待后已接收成交仍入账。
- 有界队列满时拒绝新成交，正常关闭时处理完已接收的队列。
- 在账户、成交、持仓及平仓分配 SQL 全部执行后注入异常，验证所有业务表完整回滚；服务停止提供账本操作，重启后可重试。
- 首次初始化中途故障不留下部分账本；新服务恢复后只导入一次。
- 运行配置冲突、重复写进程、迁移或账本数据损坏均拒绝恢复。
- 同合约同方向跨账户汇总、多空保留、各账户费用互不影响。
- API 筛选、分页、十进制字符串、404/422/503、写入口未开放，以及账本可用时交易就绪仍为 503。
- 不合法的配置、未加引号的金额、重复或未知账户/合约、重复成交与超量平仓在建库前拒绝；配置校验及 OpenAPI 导出无数据库副作用。

发布包通过 `scripts/smoke_package.py` 在临时目录进行两次真实进程启动，使用不包含 Python/Node 的 PATH。验证页面、迁移资源、账户和查询结果；首次强制终止后重启，结果一致，并通过数据库完整性及外键检查。此处测试已提交账本的进程恢复；未把它视为行情断线补全或整机断电验证。

## 后续系统验收

- **POS 全流程**：将当前内部已成交入口接入经过风控检查的模拟执行，验证订单拒绝或成交与持仓更新的一致性；接入持久化跨日处理。
- **MD-01 至 MD-03**：两源实际接入，各自断线、补全、重复发送与错误数据处理，不能漏掉中间阈值穿越或重复产生风险信号。
- **RISK-01 至 RISK-04**：实时指标更新、资金/持仓规则、动作状态；浮亏达到阈值后从真实入口发起开仓并被阻止。
- **SET-01 至 SET-03**：收盘封账、完整性检查、全账户事务日结、重试、报表生成；核对报表与账本，不重复入账。
- **EX-01 至 EX-04**：完整规则回放、实时仪表盘、业务参数配置、多账户对比，在核心闭环之后验收。
- **DEL**：完整源码、文档、测试方案、可执行目录、代码截图和现场演示；基础打包启动记录见[工程骨架验证](工程骨架验证.md)。
