## 固定核算预期

先按[业务口径与计算样例](业务口径与计算样例.md)独立计算，再将结果记录到 `testdata/expected/accounting-two-days.json`。预期值不由被测计算函数生成。

三个账户、三个交易所示例合约、两个连续交易日覆盖开仓、平今、平昨、部分平仓、空仓结算与跨日基准重置。每个账户核对平仓盈亏、持仓结算盈亏、费用、日净盈亏、余额、保证金和可用资金，同时核对清算明细与汇总。

边界测试包括：

- 超量平仓、错误今昨仓或多空方向，不产生部分状态变更。
- 重复成交不重复入账，相同编号不同内容拒绝。
- 账户、合约、交易日不匹配，成交乱序和合约规则变化拒绝。
- 有持仓却缺少行情/结算价时明确失败，不能使用零价格。
- 结算后禁止追加成交；重复相同价格日结返回原结果，不同价格不能覆盖；未日结不能跨日。
- 二进制浮点数、NaN、Infinity、非法数量和超范围输入拒绝。
- 调用方改变 Decimal 全局精度、舍入方式或陷阱设置，不影响核算。
- 同一多空方向拆批不改变保证金，跨账户对向持仓不抵扣资金占用。

## 账本事务与恢复验证

测试位于 `backend/tests/integration/test_ledger.py` 和 `backend/tests/unit/test_ledger_config.py`，使用真实临时 SQLite 数据库及 FastAPI lifespan，覆盖：

- 首次初始化、两次重启、重复成交与冲突成交，不重复计费或覆盖历史来源。
- 20 个并发调用按接收顺序提交，不丢失版本、费用与持仓更新。
- 事务提交前数据库读者和应用查询均只看到旧状态；取消等待后已接收成交仍入账。
- 有界队列满时拒绝新成交，正常关闭时处理完已接收的队列。
- 在账户、成交、持仓及平仓分配 SQL 全部执行后注入异常，验证所有业务表完整回滚；服务停止提供账本操作，重启后可重试。
- 首次初始化中途故障不留下部分账本；新服务恢复后只导入一次。
- 运行配置冲突、重复写进程、迁移或账本数据损坏均拒绝恢复。
- 同合约同方向跨账户汇总、多空保留、各账户费用互不影响。
- API 筛选、分页、十进制字符串、404/422/503、写入口未开放，以及账本可用时交易就绪仍为 503。
- 不合法的配置、未加引号的金额、重复或未知账户/合约、重复成交与超量平仓在建库前拒绝；配置校验及 OpenAPI 导出无数据库副作用。

发布包通过 `scripts/smoke_package.py` 在临时目录进行两次真实进程启动，使用不包含 Python/Node 的 PATH。验证页面、迁移资源、账户和查询结果；首次强制终止后重启，结果一致，并通过数据库完整性及外键检查。此处测试已提交账本的进程恢复；未把它视为行情断线补全或整机断电验证。

## 交易与风控闭环验证

新增 `backend/tests/unit/test_risk.py`（13 项）和 `backend/tests/integration/test_trading.py`（18 项），对应原题资金/持仓规则与熔断验收：

- 阈值前、等于阈值、超过阈值的判断；用独立浮盈亏验证不混入权益、已实现盈亏或费用，外部 Decimal 精度设置不影响规则。
- A 浮亏 2980 元不熔断、3000 元触发熔断，真实下单返回拒绝且账本不变；反弹保持熔断，平仓和其他账户交易正常。
- 单品种总名义敞口保留多空绝对额；两个并发开仓请求只有不越限的请求成交，预计可用资金不足拒绝。
- 告警及敞口进入/退出，熔断只触发一次，重复帧不产生重复风险事件。
- 无价格、过期、跳帧、冲突帧、缺合约、错误交易日和不符合价位的价格处理；重发旧帧不延长有效期，重启后等待新帧。
- 同订单编号重试返回原接受/拒绝结果，参数冲突返回 409；取消等待不导致重复成交。
- 成交、账户、持仓和风险日志写入后注入异常，确认整个事务与日志检查点回滚；重试恢复正确结果。
- 交易规则不允许在恢复时变更或被关闭；日志结果被修改、首条或最后一条日志被删除时拒绝恢复。
- 本地会话凭据、来源检查、API 金额类型、非法参数、风险查询及真实 FastAPI 生命周期。

`uv run --project backend --locked python scripts/demo_risk.py` 使用独立临时数据库与真实源码子进程，运行上述阈值、拒单、平仓和独立账户场景，然后强制退出并重启，核对账本、风险事件和熔断状态。`make verify` 还运行同一场景的 `--packaged` 版本，子进程 PATH 不包含 Python/Node。

`backend/tests/integration/test_market.py` 新增 23 项，使用两个独立 FastAPI 源应用、真实临时 SQLite 和可控时钟。HTTPX 测试传输按端口路由请求，不将这部分当作操作系统进程验证：

- 暂停开平仓；历史帧虽刚收到但尚未追平时，不能放行交易。追平后恢复；重复帧不重复应用。

- 删除已应用原始帧或事件追踪记录、改坏游标或摘要时拒绝恢复；冻结场景禁止修改或关闭，允许传输故障设置调整。

## 日结、跨日持久化与日报

`test_settlement.py` 14 项和 `test_settlement_flow.py` 8 项覆盖：

- 独立手算三个账户两日的平仓盈亏、持仓盈亏、费用、余额、保证金及可用资金，另核对多空敞口汇总。
- 结转前后持仓基准、今昨仓与当日累计值；次日以昨结算价平昨，历史成交与首日报告不变。
- 封账后拒绝开平仓，收盘逻辑时间已到但调度未执行时也不能放行；没有收盘或数据未齐时禁止清算。
- 两个交易日都已过去且行情仍有缺口：先恢复首日收盘数据，再清算结转并处理次日，不跳日或丢失中间熔断。
- 重复日结/结转返回原结果，变更或缺少结算价格拒绝；清算前不能跳到下一日。
- 第二个账户 SQL 更新后注入异常，分别验证全账户清算与结转整体回滚；重启后重试只增加一次修订。
- 结算态、结转态和跨日成交后重启，核对交易日志、账本、持仓与报告；删改报告或改完报告重新算摘要均拒绝恢复；删除或修改前日历史平仓分摊也会被完整日志核对发现。
- HTTP 本地权限、阶段查询、报告查询/下载、文件写入失败与重试，以及会话边界和配置建库前校验。

`test_report.py` 22 项覆盖中文离线 HTML、金额字符串原样保留、账户/合约等文本 HTML 转义、安全日期文件名、原子替换、失败后临时文件清理和同快照重试。渲染器只展示输入，不自行汇总财务值。

`uv run --project backend --locked python scripts/demo_settlement.py` 启动两个真实行情进程与后端，首日自动收盘清算，次日实际平昨后强制退出并恢复，继续完成第二日日结。三个账户两日盈亏、余额、保证金与独立手算一致；重复清算不重复入账，HTML/JSON 与冻结快照一致。`make verify` 包含同一脚本的发布包版本。完整步骤和金额见[日结与风控日报](日结与风控日报.md)。
