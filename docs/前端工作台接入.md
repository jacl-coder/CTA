# 前端工作台接入

更新日期：2026-09-13。唯一外部依据仍为[机试原题](机试题目-多品种期货交易风控系统.md)。本次在已有 Python 服务和 React 结构中接入业务界面，实时仪表盘、多账户对比属于原题附加项；交易表单是自主选择的演示入口。

## 页面与结构

- `app`：路由、全局账户筛选、连接提示和统一工作台上下文。
- `api`：生成的 OpenAPI 类型、请求错误解析、写请求令牌处理。
- `hooks/usePolling.ts`：顺序轮询、超时取消、查询切换与旧请求隔离。
- `components`：表格面板、风险标签和十进制金额展示。
- `features/overview`：全账户指标、账户明细和勾选批量对比。
- `features/positions`：账户/品种持仓、今昨仓、跨账户汇总和成交分页。
- `features/market`：完整价格、源连接状态、连续接收与完整应用进度。
- `features/events`：风险状态转换、原发生帧、发现时间和补数标记。
- `features/trading`：模拟开仓、平今、平昨、订单结果核对和手工价格输入。
- `features/reports`：封账、清算、结转、冻结日报与 HTML/JSON 下载。

订单记录涵盖当前运行的全部交易日，以全局行情帧追溯；成交明细另有明确交易日。全局账户筛选影响业务明细和订单记录；顶部汇总始终标明“全账户”。交易表单初始采用筛选账户，进入后以下单表单中的账户为准，避免后台筛选变化悄然改变正在编辑的委托。

## 页面布局与记录时间

每页仅保留顶部“刷新”入口，同时更新工作台快照及当前已打开的列表、汇总或冻结日报；保留表单、筛选条件与页码。不触发下单、清算或导出，日报“重新导出”仍是独立业务操作。自动轮询保持原频率，冻结日报仅在进入、选择日期或主动刷新时读取。

七个页面统一采用侧边导航、资金卡片、状态提示和业务面板。账户总览优先展示权益、盈亏及风险；交易页展示当前报价、今昨仓和实际买卖方向；行情页展示双源连接与补齐进度；日结页优先说明当前阶段、自动或手工清算方式及日报数量。技术核对信息放在展开区。窄屏改为横向导航、单列面板，宽表格在面板内滚动；切换页面回到顶部。

- 订单列表首列显示处理时间，对应 `processed_at_ms`。服务端消费订单时读取一次实际时钟，时间与成交或业务拒单结果共同写入 SQLite 交易日志；持久化成功后才发布到页面。
- 成交列表首列显示成交时间，对应 `executed_at_ms`。本地模拟立即成交，使用对应订单结果中的处理时间，并通过账户及成交编号关联。
- 风险事件保留原发生时间、发现时间和补数标记，现在显示完整日期及毫秒，便于核对跨日与补数场景。
- 页面统一将业务日期标为“模拟交易日”，并在顶部固定显示当前模拟交易日。记录时间统一按 `Asia/Shanghai`（北京时间）展示，明确标为实际处理、发生或发现时间；两者可能不同，也均不是页面刷新时间。
- 重试和重启沿用首次已提交的处理时间，不再次取当前时钟。旧日志缺少时间时仍可恢复，初始化成交及无时间的历史记录显示“未记录”，不按行情帧推算。

本次没有修改旧日志或初始化配置摘要，也无需数据库表迁移。升级后应停止旧后端，再执行 `make run`；只有运行新版后端后处理的新订单才会记录时间。

## 数据与一致性

新增 `GET /api/workspace`，集中返回同一次读取中的账户、持仓、风险、行情源、日结阶段、冻结清算计划和可用能力。路由读取已提交内存快照，期间不向事件循环让出执行权；10 项后端契约测试覆盖模式、金额、提交版本、重启和存储故障。

页面在上一次请求结束后等待 500 ms 再请求完整快照；这是准实时展示间隔，不承诺端到端延迟。首版使用 HTTP 轮询，替代早期设计中的 SSE。机试没有要求 SSE；当前规模用完整快照可以减少重连增量协议及混合版本问题。展示可能跳过中间帧，后端仍逐帧处理完整行情并持久化全部风险事件。

请求 2.5 秒超时；失败立即标记旧数据，距成功读取达到 3 秒也视为过期。断线时保留上次数据并禁用写操作，恢复后自动读取完整快照。查询切换立即隐藏原账户/页码的数据，迟到响应不能覆盖新查询。成交、订单和风险事件每页请求 21 条，展示 20 条，用第 21 条判断能否翻页，不虚构总条数。

金融金额均为后端 Decimal 字符串，前端仅插入千分位及补足小数展示，不经过 Number 求和或舍入。缺失估值显示“—”，不会用零替代。HTTP 连通、行情有效、账户可开仓分别显示；最终放行和拒绝由原有后端队列决定。

## 写入与异常处理

每次写请求临时获取本地会话令牌，不持久化令牌。只有证明未授权受理的 401 会自动获取新令牌重试，网络异常不自动重复提交。

订单在请求前生成 `request_id`，将完整请求按运行标识保存在本标签页 sessionStorage。回包丢失时禁止新建委托，允许查询原结果或使用完全相同的请求重试；刷新页面也保留待核对订单。存储不可用时仍能在当前页面核对，但刷新无法恢复未确认请求。后端订单幂等是最终保障。

日结按钮使用服务端阶段、收盘帧和冻结计划判断可操作性，清算价不会取当前市场价替代。清算完成后日报读取数据库中的冻结结果；下载或文件导出失败不会重新入账，可以独立重试导出。手工价格入口只在手工模式出现，双源模式不能用它覆盖行情。

## 启动与演示

完成依赖安装后，在仓库根目录运行：

```bash
make run
```

打开 `http://127.0.0.1:8004`，默认使用唯一的 `configs/default.yaml`。顶部选择“正常运行”“手工演示”或“故障与清算”，再点击“进入场景”；重演使用“重新开始当前场景”。无需切换后端服务或端口。

修改 React 使用热更新时，另开终端执行 `CTA_API_TARGET=http://127.0.0.1:8004 npm --prefix frontend run dev` 并访问 5173。

选择“手工演示”后按以下步骤操作：

1. 打开“模拟交易”，输入 rb 3500、铁矿石 800、IF 4000，提交第 1 帧。
2. 账户 A 选择螺纹钢、多头、开仓 1 手并提交，持仓由 2 手增加为 3 手。
3. 提交第 2 帧：rb 3400，其余不变。A 浮亏为 3000 元，达到 3% 阈值，开仓按钮禁用。
4. 提交第 3 帧：rb 恢复 3500，其余不变。浮亏回到零，当日熔断继续保持；风险事件页保留阈值触发记录。
5. 打开“日结与日报”，依次封账、按计划结算价清算。A 的期末余额应为 100390.00 元、保证金 10530.00 元；全账户余额 1299879.00 元。下载 HTML/JSON。
6. 结转下一交易日，前日冻结日报保持原值；尚无次日行情时仍不能交易。在交易页继续提交第 4～6 帧，再完成第二日日结。

手工报价默认有效 300 秒，过期后需要下一帧；当日三帧用完后进入封账清算。重新开始会新建数据，旧账本和日报仍保留。

“故障与清算”使用两个独立行情源，每秒一帧，约 96 秒后完成两日清算。所有场景都使用当前工作台网址。

写请求捕获页面当前的运行编号，以 `X-CTA-Run-Id` 发送；切换时串行关闭旧资源，旧页面写请求被拒绝。工作区更新到新运行后会重建业务页面，清除旧分页、报价编辑和日报选择。
