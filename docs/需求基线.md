## 2. 项目目标与约束

从零搭建一个多品种期货交易风控与清算系统，服务多个期货策略账户，覆盖行情接入、持仓管理、盘中风控、盘后清算及风控日报。

业务背景涉及上期所（SHFE）、大商所（DCE）、中金所（CFFEX）的若干品种。具体品种、合约及数量尚未确定。

题目明确的约束：

- 允许使用开源库、AI 编程助手和网络资源。
- 无需对接真实交易所；可以使用模拟数据，但需说明方案的合理性及选择理由。
- 开发语言不限，题目列举的语言是建议。
- 必须提交可编译运行的完整项目。

## 3. 核心必做要求

以下编号用于后续关联实现内容和测试方案。

### 3.1 行情接入

来源：题目“行情接入”。

- **MD-01 多源接入**：接入至少 2 个行情源，模拟或真实均可，并说明选择理由。
- **MD-02 行情更新**：获取实时或准实时行情；数据格式与更新频率自行设计。
- **MD-03 中断恢复**：行情源中断后恢复时，正确补全缺失数据，且不产生重复或错误的风险信号。

验收依据：能够展示两个行情源的接入与行情更新，并在中断、恢复场景下验证缺失数据补全及风险信号的正确性。

边界：原文未指定协议、字段、主备切换方式、多源价格选择规则，也未规定两个行情源必须采用不同供应商或不同协议。采用何种方案需要在设计中说明。仅有备用源继续提供行情，不能替代缺失数据补全要求。

### 3.2 持仓管理

来源：题目“持仓管理”。

- **POS-01 持仓维护**：维护各策略账户的持仓数据，支持开仓与平仓记录。
- **POS-02 多维查询**：支持按账户维度和品种维度查询。
- **POS-03 数据机制**：自行设计并说明持仓数据来源与更新机制。
- **POS-04 多账户核算**：考虑多账户场景下的持仓汇总与独立核算。

验收依据：开平仓记录能够反映在对应账户的持仓中；可按账户、品种查询，并展示多账户汇总和各账户独立核算的结果。

边界：原文没有要求真实交易接入或完整撮合系统。订单、成交和持仓如何衔接需要设计，不能将订单提交直接等同于成交记录。

### 3.3 盘中风控

来源：题目“盘中风控”。

- **RISK-01 实时监控**：实时监控风险指标。
- **RISK-02 维度覆盖**：风险指标至少覆盖资金维度和持仓维度；具体指标及阈值自行设计。
- **RISK-03 风控动作**：触发阈值时执行预定义动作，原文列出的动作包括告警、限制下单、熔断；规则与动作的对应关系需要设计。
- **RISK-04 熔断验收**：某账户单日浮亏达到预设阈值时，自动触发熔断，阻止该账户继续开仓。

题目明确的熔断验收过程：

1. 某账户存在持仓，系统计算其单日浮动盈亏。
2. 浮亏达到预设阈值。
3. 系统自动触发该账户熔断。
4. 该账户后续开仓请求被阻止。

边界与示例说明：

- 账户净值、最大回撤、当日盈亏、单品种敞口、集中度是指标示例，不要求全部实现。
- “初始资金的 3%”是阈值示例，不是固定参数。
- “单日浮亏”的计算口径需明确，不能未经说明替换为累计亏损或当日总亏损。
- 熔断必须产生实际的开仓阻止效果，仅记录告警或展示熔断状态不能满足 RISK-04。
- 熔断解除条件、是否允许平仓、是否强制平仓、状态是否持久化，原文没有具体规定，留待设计。

### 3.4 盘后清算与风控日报

来源：题目“盘后清算与风控”。

- **SET-01 逐日盯市**：每日收盘后完成逐日盯市计算，包含盈亏结算和保证金核算。
- **SET-02 风控日报**：生成每日风控报表，包含盈亏汇总、风险敞口、关键指标等。
- **SET-03 报表形式**：报表格式自行设计，可以采用文本、HTML、PDF 等形式。

验收依据：能够展示一个交易日的清算输入、盈亏与保证金计算结果，以及对应风控日报；计算结果应可复核。

边界：逐日盯市是核心要求，仅展示相对开仓均价的浮动盈亏不能视为完成逐日清算。昨结算价、当日结算价、当日开平仓及跨日持仓如何参与核算，需要在计算口径中说明。原文未规定具体公式、费用模型、清算触发方式或报表布局。
