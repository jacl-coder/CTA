# 交付与原题验收

更新日期：2026-09-10。唯一外部依据为[机试原题](机试题目-多品种期货交易风控系统.md)。本文组织已有实现的验收证据和交付方式；内部验证通过不代表机试方已验收。

## 交付包与启动

开发环境执行：

```bash
make check
make test
make package
make verify
```

`make package` 先构建 React 和 PyInstaller 程序，再生成 `dist/cta-risk-delivery-linux-x86_64.tar.gz` 及同名 `.sha256`。归档包含：

- `backend/`、`frontend/`、`scripts/`、`packaging/`：完整源码、测试、依赖锁及构建脚本。
- `configs/`、`testdata/`：演示配置、独立手算预期。
- `docs/`、`README.md`：原题、使用与技术说明、测试方案、现场演示、答辩要点、代码展示图。
- `dist/cta-risk/`：含解释器、依赖、前端资源和 SQL 迁移的可执行目录。
- `MANIFEST.json`：文件 SHA-256、大小、可执行权限、构建环境、基准提交及是否有未提交改动。

交付包使用当前工作区的源码；未提交文件会在清单中明确标记，不能仅用基准提交号代替包内源码版本。各文件摘要用于核对完整性，不是第三方签名。数据库、历史运行数据、开发用虚拟环境、node_modules 和本地环境变量文件不进入交付包。

评审在兼容 Linux x86_64 环境解压并直接启动，无需安装 Python、Node、uv 或 npm：

```bash
sha256sum -c cta-risk-delivery-linux-x86_64.tar.gz.sha256
tar -xzf cta-risk-delivery-linux-x86_64.tar.gz
cd cta-risk-delivery
./dist/cta-risk/cta-risk serve --config configs/live-demo.yaml
```

浏览器打开 `http://127.0.0.1:8004`，退出按 `Ctrl+C`。数据库和日报写入解压目录内的 `var/`。必须保留整个 `dist/cta-risk/`；只复制可执行文件会缺少运行资源。

默认配置自动启动 8301/8302 两个源，每秒一帧，每 30 分钟自动清算并进入下一模拟交易日。无需手工报价；连接或补数未完成时等待就绪。以下为固定故障与两日清算验收入口：

```bash
./dist/cta-risk/cta-risk serve --config configs/settlement-demo.yaml
```

访问 8003，子进程监听 8201/8202。启动后约 24 秒完成固定两日场景；详细展示顺序见[现场演示与答辩](现场演示与答辩.md)。源码方式运行使用 `make run`，切换配置使用 `make run CONFIG=...`。

## 原题核心条款核对

### 行情接入

原题要求至少两个行情源、实时或准实时更新、中断恢复补全、不出现重复或错误风险信号。

已实现两个独立 HTTP 模拟源，源 A 覆盖 SHFE 螺纹钢，源 B 覆盖 DCE 铁矿石与 CFFEX 股指期货。配置定义价格点、更新频率和故障窗口，共享冻结逻辑起点；历史数据可确定性补拉。模拟方案可以重复制造“中断期间跌破阈值又反弹”的场景，并将连续接入与中断接入结果逐项比较。

入口与证据：`marketdata/client.py`、`application/market.py`、`simulator/`；`test_market.py` 与 `scripts/demo_market.py --packaged`。验收关注缺口期间禁单、原始连续进度与应用进度分离、A/10 与 B/32 各一次熔断、后端及单个源退出后的恢复。

边界：目前适配固定有限模拟历史。真实源需实现其自身历史补拉和协议校验，不能声称现有模拟协议已直接适用于交易所。

### 持仓管理

原题要求开平仓记录、账户与品种查询、多账户汇总及独立核算，并说明来源和更新机制。

已由标记来源的初始化成交建立持仓；后续模拟订单经过后端风控后成交，进入唯一账本队列。支持多空、开仓、平今、平昨、部分平仓、FIFO 批次和费用核算。跨账户汇总数量与敞口，账户余额、保证金及结算独立计算。

入口与证据：`position/`、`application/ledger.py`、`api/ledger.py`、前端“持仓与成交”；`test_accounting.py`、`test_ledger.py` 和跨日演示。验收关注按账户/品种过滤、同合约多空分开、重复委托不新增成交、次日平昨基准正确。

### 盘中风控

原题要求资金与持仓两个维度、告警/限制/熔断，并指定“单日浮亏达到预设比例后阻止继续开仓”。

已使用持仓浮亏/初始资金作为资金规则，演示配置 2% 告警、3% 熔断；持仓规则采用单品种总名义敞口，并检查开仓后的预计敞口和可用资金。熔断状态当日保持，合法平仓在行情有效时仍允许。执行入口在后端，页面按钮只提示状态。

入口与证据：`risk/rules.py`、`application/trading.py`；`test_risk.py`、`test_trading.py`、`scripts/demo_risk.py --packaged`。独立场景核对 A 初始资金 100000：浮亏 2980 不熔断，3000 熔断、拒绝开仓；反弹、重启和原订单重试不绕过限制。

边界：原题中的最大回撤、集中度是指标举例，没有要求全部实现；本项目选取的两个维度已覆盖最低要求。没有将强平、外部消息通知或真实交易所接入追加为必做项。

### 盘后清算与风控日报

原题要求每日逐日盯市、盈亏与保证金核算，以及含盈亏、敞口和关键指标的日报。

已按配置会话边界封账，收盘行情补齐后进行全账户原子清算，冻结报告，再结转余额和持仓基准。次日首帧前继续禁单。HTML/JSON 可离线阅读，文件导出失败可以单独重试，不能重复入账。

入口与证据：`settlement/calculator.py`、`application/settlement.py`、`settlement/scheduler.py`、`report/exporter.py`；领域手算、日结集成、日报测试和 `scripts/demo_settlement.py --packaged`。验收关注两个交易日三个账户的余额与保证金、实际平昨、跨日崩溃恢复、前日日报不变和封账后拒单。

边界：使用配置中的显式会话和结算价，已验证两日流程；没有接入真实交易日历，也不支持历史结算更正。

## 原题附加项核对

- 可视化仪表盘：已实现。页面在一次快照响应后等待 500 ms 再读取，显示账户与风险，并明确断线和旧数据。后端风控仍逐帧处理。
- 配置化：已实现。账户、合约、风险阈值、敞口额度、行情场景和日结计划通过 YAML 配置。已有运行冻结业务规则，改规则需新运行。
- 多账户批量对比：已实现。账户总览可勾选多个账户比较资金、风险和限制，持仓页可跨账户汇总。
- 历史回放验证：未实现独立工具。交易日志恢复核对和模拟源补数不记作完整回测能力。

## 验证记录与有效范围

`make verify` 首先解压实际交付压缩包，核对所有文件和执行权限，然后调用解压目录中的五个验收脚本。测试控制器使用开发机 Python/PyYAML；被测程序及两个行情子进程使用包内运行时，PATH 不包含 Python/Node。这样证明交付物在本机脱离源码目录运行，不等同于已在另一台干净机器通过。

`demo_live.py --packaged` 专门验证默认持续行情：沿用 `live-demo.yaml` 的价格生成和风险规则，仅更换临时数据目录、空闲端口，并把单日缩短为 8 帧。验证双源进程、开仓、跨日平昨、强制重启后订单幂等与日报不变，并继续进入第三模拟日；正常使用仍为每 30 分钟一个模拟日。

记录输出在 `dist/delivery-verification/<归档摘要前16位>/`，包含 `result.json` 和五份日志。只有 `passed: true` 且 `archive_sha256` 与当前归档一致，才能将该记录作为此包的验证证据。修改代码后应重新构建和验证，旧归档的结果不能替代新包结果。归档 SHA-256 校验文件、对应验证目录与归档一同提供。

本机构建环境：Ubuntu 24.04.4 LTS、Linux x86_64、glibc 2.39。其他 Linux 发行版、较旧 glibc、Windows 与 macOS 没有完成兼容性验收。长期运行、真实交易接入、容量压测和多用户权限体系也未验证；当前交付范围是可复现的本地机试系统。
